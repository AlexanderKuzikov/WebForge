# Дневник Разработки

Этот документ отслеживает ключевые архитектурные решения и этапы разработки проекта.

---

### **День 0: Инициализация проекта и Фундаментальные Архитектурные Решения**

**Дата:** 27.08.2025 (Дата инициализации, записи могут быть позднее)

**Статус:** Определение и фиксация фундаментальной архитектуры, принципов и ключевых решений.

**Описание:**
Данный пост фиксирует базовые принципы и наиболее важные архитектурные решения, принятые на старте проекта, которые формируют его основу. Эти решения будут служить ориентиром для всей дальнейшей разработки.

**Ключевые принятые решения:**

1.  **Основной стек и Цель Проекта**:
    *   **Генератор**: PHP для разработки и динамической сборки страниц из компонентов на локальном сервере.
    *   **Продакшн**: Полностью статические HTML, CSS, JS файлы, генерируемые скриптом сборки.
    *   **Конечный продукт**: Автономные, высокопроизводительные, SEO-оптимизированные статические сайты, не требующие серверного взаимодействия и внешних зависимостей (включая шрифты), максимально устойчивые к блокировкам.
    *   **Приоритет деплоя**: Максимальная скорость загрузки, отказоустойчивость, независимость, SEO. Читаемость кода не важна.

2.  **Архитектура компонентов**:
    *   **Структура**: Каждый компонент изолирован в своей директории `components/{имя-компонента}/`.
    *   **Состав**: Компонент включает `{имя}.php` (PHP-шаблон для HTML-разметки и минимальной логики), `{имя}.json` (данные/настройки компонента, **не содержит CSS-правил**) и, при необходимости, `script.js` (локальный JS).

3.  **Глобальная конфигурация**:
    *   Файл `site.json` в корне проекта служит единым источником правды для глобальных настроек (цветовая палитра, типографика, брейкпоинты, размеры контейнеров, глобальные данные сайта). Эти данные используются для генерации CSS-переменных и контента.

4.  **Управление уникальностью экземпляров компонентов (HTML ID)**:
    *   **Проблема**: Конфликты HTML `id` при множественном использовании компонента на одной странице.
    *   **Решение**: В PHP-файле каждого компонента генерируется уникальный базовый ID, основанный на имени его директории (`$componentBaseId = basename(__DIR__);`). Все внутренние `id` элемента генерируются с этим префиксом (например, `$componentBaseId . '-header'`), что гарантирует их уникальность. Предполагается, что каждая вставка компонента будет иметь уникальное имя папки (или это будет обеспечено на уровне сборки страницы).

5.  **Изоляция JavaScript**:
    *   **Проблема**: Избежать конфликтов и обеспечить, чтобы JS компонента влиял только на свой экземпляр.
    *   **Решение**: Если у компонента есть `script.js`, его PHP-файл генерирует `inline`-скрипт. Этот скрипт ожидает `DOMContentLoaded`, находит конкретный экземпляр компонента по его уникальному HTML `id` и вызывает общую функцию-инициализатор, **передавая ей найденный HTML-элемент (контейнер компонента)**. Весь JS-код в `script.js` работает **только в контексте переданного элемента** (`element.querySelector(...)`). **Полный отказ от глобальных ID и событий в JS**.

6.  **Архитектура CSS (фундамент)**:
    *   **Модульность**: Каждый компонент будет иметь свой собственный CSS-файл внутри своей директории (`components/{имя-компонента}/style.css`).
    *   **Глобальный CSS**: Основные CSS-файлы (`css/base.css`, `css/layout.css`) будут содержать только глобальные стили (переменные, нормализация, базовые стили тегов) и определения сеток макетов (CSS Grid Layouts).
    *   **Генерация переменных**: PHP-утилита читает `site.json` и генерирует CSS-файл с переменными (`:root`).
    *   **Типографика**: `html { font-size: 100%; }` и `body { font-size: 1.125rem; }` для доступности и желаемого базового размера.
    *   **Нормализация**: Используется Modern Normalize.

**Текущая главная задача и открытые вопросы (на момент "Дня 0" - переходящие на следующие дни):**

*   **Стратегия CSS-нейминга и конфликтов имен**: Как избежать конфликтов CSS-классов в масштабируемом проекте при модульной структуре CSS (например, БЭМ, уникальные префиксы, CSS Modules при сборке) и с учетом методики `scoped-стилизации`.

2.  Приступить к разработке скрипта сборки (`build.php`).
3.  Реализовать механизм генерации CSS-переменных из `site.json`.
4.  Начать реализацию базовых компонентов (`header`, `footer`, контейнеры).
