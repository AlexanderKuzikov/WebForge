\### Расширенный Промпт для LLM: Проект "WebForge" – Статический Генератор Сайтов для Устойчивой Среды



\*\*Глубинная цель и мотивация проекта (для полного понимания LLM):\*\*

Проект "WebForge" создается в условиях нарастающих информационных ограничений и блокировок, как со стороны государства, так и со стороны международных сервисов. Основная задача — обеспечить функционирование веб-ресурсов для малого бизнеса, которые будут максимально устойчивы к внешним воздействиям, работать на слабом оборудовании и не требовать постоянного обслуживания. Это достигается за счет создания \*\*полностью статических, автономных, независимых от серверного взаимодействия и внешних зависимостей (включая шрифты) сайтов\*\*. При этом ключевым фактором является \*\*высочайшая SEO-оптимизация\*\* для снижения операционных затрат и обеспечения максимальной выгоды в сложных условиях.



\*\*Цель проекта (техническая):\*\*

Создание высокопроизводительного, SEO-оптимизированного статического генератора сайтов, \*\*реализованного на PHP\*\*. Этот генератор будет преобразовывать компонентную структуру проекта в \*\*чистые, автономные, статические HTML, CSS и JS файлы\*\*, не требующие серверного взаимодействия для функционирования. Главный приоритет финальной сборки — \*\*максимальная скорость загрузки, исключительная отказоустойчивость, независимость от внешних ресурсов и превосходные показатели SEO\*\*. Читаемость и поддерживаемость кода деплоя не важны, главное — функциональность в жестких условиях.



\*\*Философия и ключевые принципы:\*\*



\*   \*\*Абсолютная автономность\*\*: Сгенерированные сайты не должны иметь зависимостей от внешних CDN, API, шрифтов или любых других ресурсов, которые могут быть заблокированы или недоступны. Все необходимое должно быть включено в статический пакет.

\*   \*\*Высочайшая производительность\*\*: Достигается за счет полного отказа от серверной логики на продакшене, минимизации ресурсов, оптимизации изображений, критического CSS. Сайт должен работать максимально быстро даже на слабом оборудовании.

\*   \*\*Исключительная отказоустойчивость и взломоустойчивость\*\*: Отсутствие серверной части на продакшене делает сайт иммунным к большинству стандартных атак и проблем с хостингом.

\*   \*\*Без сторонних фреймворков\*\*: Весь HTML, CSS, JavaScript пишется с нуля. Идеи визуального вида могут быть заимствованы из существующих библиотек (например, Bootstrap), но \*\*реализация всегда кастомная, путем декомпозиции и переработки идей в полностью изолированные, независимые компоненты собственного изготовления.\*\*

\*   \*\*Mobile-First\*\*: Стилевое проектирование начинается для минимального разрешения (320px) и расширяется для больших экранов через медиа-запросы. Использование относительных единиц (`rem`, `em`, `%`, `vw`/`vh`) вместо фиксированных (`px`).

\*   \*\*PHP для разработки, Статика для деплоя\*\*: Удобная разработка на локальном PHP-сервере с live-preview. Финальный результат — оптимизированная статическая сборка для публикации.

\*   \*\*Минимум JavaScript\*\*: Приоритет отдается решениям на HTML/CSS. JavaScript используется только в случаях, когда CSS не справляется с реализацией эффектов или функциональности. \*\*Предпочтение нативным HTML-элементам\*\*, если они обеспечивают нужную функциональность без JS (например, `<details>` и `<summary>` для аккордеона).

\*   \*\*Семантическая верстка\*\*: Финальная сборка должна включать корректное использование тегов `<header>`, `<main>`, `<footer>` и других для улучшения SEO и доступности.

\*   \*\*Максимальная SEO-оптимизация\*\*: Облегченный код, быстрая загрузка, семантическая верстка, корректные мета-теги, критический CSS, исключение блокирующих рендеринг ресурсов.

\*   \*\*Стратегический поворот в концепции\*\*: Проект изменил позиционирование с "производителя/монтажника" на "инноватор, лидер отрасли с патентами". Это стратегическое изменение, требующее пересмотра структуры и контента, начиная с mobile-first.



\*\*Архитектура проекта (текущая версия, включая принятые решения):\*\*



1\.  \*\*Компонентная система:\*\*

&nbsp;   \*   Каждый компонент — это отдельная директория в `/components/`.

&nbsp;   \*   \*\*`{имя\_компонента}.php`\*\*: PHP-шаблон, генерирующий HTML, содержит минимальную PHP-логику для вывода данных и базовых структур (циклы, условия).

&nbsp;   \*   \*\*`{имя\_компонента}.json`\*\*: Файл с данными и настройками компонента. \*\*Хранит все настраиваемые данные\*\* (тексты, пути к изображениям, ссылки, флаги состояний, списки элементов и т.д.). \*\*Не содержит CSS-правил.\*\*

&nbsp;   \*   \*\*`script.js` (опционально)\*\*: Локальный JavaScript для конкретного компонента.



2\.  \*\*Глобальные настройки:\*\*

&nbsp;   \*   \*\*`site.json`\*\*: Файл в корне проекта, единый источник правды. Содержит:

&nbsp;       \*   \*\*`theme`\*\*: `colors` (цветовая палитра), `typography` (`fontFamilyBase`, `fontSizeBase`, `lineHeightBase`), `layout` (`containerMaxWidth`, `gridGap`, `breakpoints`).

&nbsp;       \*   \*\*`siteInfo`\*\*: Глобальные данные (логотип, контакты и т.д.).

&nbsp;       \*   Эти данные используются для генерации CSS-переменных и контента.



3\.  \*\*CSS-структура (финализированные подходы и текущие вопросы):\*\*

&nbsp;   \*   \*\*Генерация CSS-переменных\*\*: Отдельная PHP-утилита читает `site.json` и генерирует CSS-файл с переменными (`:root`) (или вставляет блок `<style>` в `<head>`). Это обеспечивает глобальную консистентность и легкость смены темы.

&nbsp;   \*   \*\*Базовая типографика и единицы измерения (решено)\*\*:

&nbsp;       \*   `html { font-size: 100%; }` (для доступности, 1rem ≈ 16px).

&nbsp;       \*   `body { font-size: 1.125rem; }` (для желаемого базового текста 18px).

&nbsp;       \*   Все остальные `rem` (отступы, поля) и `em` (медиа-запросы) рассчитываются от базовых 16px.

&nbsp;   \*   \*\*Сброс стилей (решено)\*\*: Используется Modern Normalize.

&nbsp;   \*   \*\*Макеты (Layouts, решено)\*\*:

&nbsp;       \*   \*\*Подход\*\*: Предопределенные \*\*CSS Grid Layouts\*\* (использующие `grid-template-areas`) в глобальном CSS. Активируются классами на `<body>` (например, `.layout-sidebar-left`).

&nbsp;       \*   \*\*Примеры\*\*: `layout-default`, `layout-sidebar-left`, `layout-sidebar-right`, `layout-two-sidebars`, `layout-sidebar-menu-left`.

&nbsp;   \*   \*\*Модульность CSS Компонентов (ключевое решение)\*\*:

&nbsp;       \*   \*\*Каждый компонент будет иметь свой собственный CSS-файл\*\* внутри своей директории (`components/имя\_компонента/style.css`).

&nbsp;       \*   \*\*Глобальный CSS\*\* (`css/base.css`, `css/layout.css`): Содержит только действительно общие стили (переменные, нормализация, базовые стили тегов, определения сеток макетов, утилитарные классы).

&nbsp;       \*   \*\*Scoped-стилизация (новая методика)\*\*: Глобальные классы переопределяются только внутри корневого контейнера конкретного компонента (`.my-component .global-class { ... }`). \*\*Классы корневого контейнера компонента должны формироваться по имени его каталога.\*\*

&nbsp;   \*   \*\*Проблема уникальности CSS-селекторов/классов (открытый вопрос, зафиксирована)\*\*: Как избежать конфликтов имен при модульной структуре CSS (например, БЭМ, уникальные префиксы, CSS Modules при сборке).



\*\*Ключевые реализованные решения (подтверждено и детализировано):\*\*



1\.  \*\*Уникальные HTML ID для экземпляров компонентов\*\*:

&nbsp;   \*   В PHP компонента: `$componentBaseId = basename(\_\_DIR\_\_);`.

&nbsp;   \*   Внутренние ID генерируются с суффиксами (например, `$componentBaseId . '-header'`, `$componentBaseId . '-item-' . $index`).

&nbsp;   \*   \*\*Важно\*\*: Предполагается, что \*\*каждая вставка компонента будет иметь уникальное имя папки\*\* (или это будет обеспечено на уровне сборки страницы).



2\.  \*\*Изолированный JavaScript для компонентов\*\*:

&nbsp;   \*   PHP-файл компонента проверяет наличие `script.js` и, если он есть, генерирует `inline`-скрипт.

&nbsp;   \*   Этот `inline`-скрипт ждет `DOMContentLoaded`, находит конкретный экземпляр компонента по его уникальному HTML `id`.

&nbsp;   \*   `inline`-скрипт вызывает общую функцию-инициализатор (например, `initializeComponent`), \*\*передавая ей найденный HTML-элемент (контейнер компонента)\*\*.

&nbsp;   \*   Локальный `script.js` компонента написан так, чтобы принимать этот элемент и работать \*\*только в его контексте\*\*, используя `componentElement.querySelector()` для поиска внутренних элементов.

&nbsp;   \*   \*\*Полный отказ от глобальных ID и событий в JS\*\* — всё делается через локальные классы или `data`-атрибуты внутри контекста компонента.



\*\*Процесс разработки и сборки:\*\*



1\.  \*\*Инициализация проекта\*\*:

&nbsp;   \*   Запуск локальных PHP/JS утилит для автоматического создания каталогов компонентов, базовой структуры файлов и настроек.

&nbsp;   \*   Формирование глобального `site.json` и базового CSS-файла.



2\.  \*\*Динамичная разработка\*\*:

&nbsp;   \*   Редактирование и тестирование компонентов на локальном PHP-сервере с live-preview.

&nbsp;   \*   Компоненты подключаются динамически через PHP с чтением JSON-настроек.

&nbsp;   \*   \*\*Приостановка кодирования\*\*: Согласовано, что сначала обсуждается и согласовывается концепция/структура, затем — реализация в коде.



3\.  \*\*Статическая сборка\*\*:

&nbsp;   \*   После утверждения всех изменений запускается скрипт сборки (`build.php`).

&nbsp;   \*   Генерация статических HTML, CSS, JS файлов в папку `/build/`.

&nbsp;   \*   В финальной сборке все CSS-файлы (base.css, layout.css, component.css из папок компонентов) и JS-файлы \*\*объединяются и минимизируются\*\* в один `style.css`/`script.js`.

&nbsp;   \*   Код финальной сборки оптимизирован для скорости и SEO (минимизация, объединение, \*\*Critical CSS\*\*, семантическая верстка).



4\.  \*\*Автоматизация (локальные утилиты)\*\*:

&nbsp;   \*   Интеграция собственных утилит на PHP и JavaScript для:

&nbsp;       \*   Генерации CSS из `site.json`.

&nbsp;       \*   Автоматизации минификации, объединения файлов.

&nbsp;       \*   Поддержки live-preview.

&nbsp;       \*   Генерации финальных статических файлов.

&nbsp;   \*   Важность автоматизации генерации файлов и шаблонов для новых блоков.
