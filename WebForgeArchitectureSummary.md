# WebForge Project: Сводка Архитектурных Обсуждений

Этот документ суммирует ключевые архитектурные решения и уточнения, принятые в ходе недавних обсуждений для проекта генератора статических сайтов WebForge.

## 1. `webforge.json`: Единственный Источник Правды (SSOT)

Мы подтвердили и усилили роль `webforge.json` как центрального, декларативного файла, содержащего всю структуру сайта, данные контента и глобальные конфигурации. Это сохраняет преимущества единого, легко версируемого источника данных для всего проекта.

**Ключевые характеристики `webforge.json`:**

- **Всеобъемлющий:** Хранит все страницы, их экземпляры компонентов, специфичные для компонентов данные, глобальные настройки темы (цвета, типографика, брейкпоинты), структуры навигации и другие данные, относящиеся ко всему сайту.
- **Декларативный:** Описывает, _что_ должен представлять собой сайт, а не _как_ он должен быть построен.
- **Масштабируемый:** Анализ подтверждает, что даже для больших сайтов (500-2500 страниц) размер файла (2-10 МБ) является управляемым и не создает значительного узкого места в производительности для современных PHP-интерпретаторов. Это подтверждает его использование в качестве SSOT.

## 2. Критическое Архитектурное Изменение: Введение Полноценного PHP-Сайта для Разработки

Произошел значительный сдвиг от прямой генерации статического HTML к промежуточной фазе, включающей полностью функциональный PHP-сайт для разработки. Этот подход обеспечивает максимальную гибкость, возможность отладки и использование привычных инструментов PHP-разработки.

**Новый Поток Работы:**
`webforge.json` → `webforge_php_generator.php` → `_dev_site/` (Сервер Разработки PHP) → `build.php` → `build/` (Статический HTML)

**Подробности новой фазы:**

### 2.1. `webforge_php_generator.php`

- **Назначение:** Это новый ключевой скрипт. Он считывает файл `webforge.json`.
- **Вывод:** Генерирует полный, динамический веб-сайт на базе PHP в отдельную директорию (например, `_dev_site/`).
- **Содержимое `_dev_site/`:** Включает:
  - Сгенерированные PHP-файлы для каждой страницы, определенной в `webforge.json` (например, `index.php`, `about.php`).
  - Копии основных PHP-файлов компонентов из `components/`.
  - Любые PHP-файлы макетов (например, из директории `layouts/`, если применимо).
  - Необходимые ассеты (CSS, JS, изображения) из источника разработки.
- **Обработка Данных:** Сгенерированные PHP-файлы страниц и компонентов внутри `_dev_site/` структурированы для получения данных. PHP-файлы компонентов (например, `components/header/header.php`) будут получать свои специфические данные экземпляра через переменную `$data` и глобальные конфигурации/настройки темы через переменную `$globalConfig`.

### 2.2. Фаза Разработки (`_dev_site/`)

- **Среда:** Разработчики будут запускать стандартный PHP-сервер (например, Apache, Nginx или встроенный сервер PHP), указывая его корневой директорией `_dev_site/`.
- **Преимущества:**
  - **Полная Отладка PHP:** Позволяет использовать стандартные отладчики PHP (например, Xdebug), профилировщики и функции IDE.
  - **Привычный Рабочий Процесс:** Обеспечивает привычный опыт разработки на PHP.
  - **Динамические Предпросмотры:** Страницы можно просматривать динамически на локальном сервере перед статической компиляцией.

### 2.3. Обновленная Роль `build.php`

- **Упрощенная Функция:** Роль скрипта `build.php` значительно упрощена.
- **Процесс:** Теперь он "обходит" динамически сгенерированный PHP-сайт в `_dev_site/`, выполняет каждый PHP-файл страницы, захватывает его вывод и сохраняет как статический `.html` файл в директории `build/`.
- **Обработка Ассетов:** Он также занимается агрегацией, минификацией и копированием файлов CSS и JavaScript в `build/`.

## 3. Структурные Шаблоны Страниц для PageBuilder

Концепция "шаблонов" для PageBuilder была уточнена и доработана. Это не просто предварительно заполненные компоненты контента, а **структурные "скелеты" страниц**.

- **Назначение:** Определять базовый макет страницы, включая расположение компонентов-плейсхолдеров, количество и соотношение колонок, параметры адаптивности, а также, возможно, тип используемого меню или макета страницы. Они представляют собой предопределенные каркасы страниц.
- **Хранение:** Эти шаблоны будут храниться в отдельном JSON-файле (например, `webforge_page_structure_templates.json`).
- **Структура Шаблона:** Каждый объект шаблона будет содержать:
  - `id`: Уникальный идентификатор (например, `"homepage_hero_3col_footer"`).
  - `name`: Понятное для пользователя имя для интерфейса PageBuilder.
  - `description`: Краткое описание структуры страницы.
  - `category`: Категория для фильтрации (например, "Главная страница", "Посадочные страницы").
  - `previewImage`: (Необязательно) URL к схематическому изображению макета.
  - `templateStructure`: Это ключевое поле будет имитировать структуру объекта `page` из `webforge.json` (`layout`, `meta`, `components`), но с минимальными или плейсхолдерными данными для его компонентов. При использовании PageBuilder `instanceId` для компонентов будут генерироваться динамически для обеспечения уникальности (например, путем добавления временной метки или случайного суффикса).
- **Интеграция с PageBuilder:** Когда пользователь создает новую страницу в PageBuilder, он выбирает один из этих структурных шаблонов. PageBuilder затем копирует `templateStructure` в новую запись страницы в `webforge.json`.
- **Будущий Потенциал:** Эта уточненная концепция закладывает основу для разработки специализированного `TemplateBuilder` или функции "сохранить как шаблон" в редакторе, позволяя пользователям определять и повторно использовать свои собственные структуры страниц.

Эта архитектурная эволюция направлена на создание надежной, гибкой и удобной для разработчиков среды для создания высокооптимизированных статических веб-сайтов с помощью WebForge.
