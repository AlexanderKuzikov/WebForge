Глубинная цель и мотивация проекта (для понимания LLM): Проект создается в условиях нарастающих информационных ограничений и блокировок, как со стороны государства, так и со стороны международных сервисов. Основная задача — обеспечить функционирование веб-ресурсов для малого бизнеса, которые будут максимально устойчивы к внешним воздействиям, работать на слабом оборудовании и не требовать постоянного обслуживания. Это достигается за счет создания полностью статических, автономных, независимых от серверного взаимодействия и внешних зависимостей (включая шрифты) сайтов. При этом ключевым фактором является высочайшая SEO-оптимизация для снижения операционных затрат.

Цель проекта (техническая): Создание высокопроизводительного, SEO-оптимизированного статического генератора сайтов, реализованного на PHP. Этот генератор будет преобразовывать компонентную структуру проекта в чистые, автономные, статические HTML, CSS и JS файлы, не требующие серверного взаимодействия для функционирования. Главный приоритет финальной сборки — максимальная скорость загрузки, исключительная отказоустойчивость, независимость от внешних ресурсов и превосходные показатели SEO. Читаемость и поддерживаемость кода деплоя не важны, главное — функциональность в жестких условиях.

Философия и ключевые принципы:

Абсолютная автономность: Сгенерированные сайты не должны иметь зависимостей от внешних CDN, API, шрифтов или любых других ресурсов, которые могут быть заблокированы или недоступны. Все необходимое должно быть включено в статический пакет.
Высочайшая производительность: Достигается за счет полного отказа от серверной логики на продакшене, минимизации ресурсов, оптимизации изображений, критического CSS. Сайт должен работать максимально быстро даже на слабом оборудовании.
Исключительная отказоустойчивость и взломоустойчивость: Отсутствие серверной части на продакшене делает сайт иммунным к большинству стандартных атак и проблем с хостингом.
Без сторонних фреймворков: Весь HTML, CSS, JavaScript пишется с нуля. Идеи визуального вида могут быть заимствованы из существующих библиотек, но реализация всегда кастомная.
Mobile-First: Стилизация начинается для минимального разрешения (320px) и расширяется для больших экранов через медиа-запросы. Использование относительных единиц (rem, em, %, vw/vh) вместо фиксированных (px).
PHP для разработки, Статика для деплоя: Удобная разработка на локальном PHP-сервере с live-preview. Финальный результат — оптимизированная статическая сборка для публикации.
Минимум JavaScript: Приоритет отдается решениям на HTML/CSS. JavaScript используется только в случаях, когда CSS не справляется с реализацией эффектов или функциональности.

Архитектура проекта (текущая версия):

Компонентная система:

Каждый компонент — это отдельная директория в /components/.
{имя_компонента}.php: PHP-шаблон, генерирующий HTML, читающий соответствующие JSON-настройки, реализующий логику уникальных ID и, при необходимости, подключающий локальный JS.
{имя_компонента}.json: Файл с данными и настройками компонента (тексты, списки, флаги). Не содержит стилей!
script.js (опционально): Локальный JavaScript для конкретного компонента.
Глобальные настройки:

site.json: Файл в корне проекта, содержащий глобальные настройки темы (цветовая палитра, шрифты, брейкпоинты, размеры контейнеров), а также общие данные (логотип, контакты). Используется для генерации CSS-переменных и контента.
CSS-структура (в разработке, требует финализации):

css/base.css: Сбросы стилей, глобальные CSS-переменные (:root), генерируемые из site.json, базовые стили для html/body.
css/layout.css: Стили для макета (контейнеры, сетка, общие стили header/main/footer).
css/components.css: Предполагается как единый файл, содержащий стили для ВСЕХ компонентов (текущая гипотеза).
В финальной сборке: Все CSS-файлы объединяются и минимизируются в один style.css (или style.min.css).
Ключевые реализованные решения (подтверждено):

Уникальные HTML ID для экземпляров компонентов:

В PHP компонента: $componentBaseId = basename(DIR);.
Внутренние ID генерируются с суффиксами (например, $componentBaseId . '-header'). Это решает проблему уникальности HTML id при множественном использовании компонента.
Изолированный JavaScript для компонентов:

Если компоненту нужен script.js, PHP-файл компонента добавляет inline-скрипт.
Этот inline-скрипт ждет DOMContentLoaded, находит родительский элемент компонента по его уникальному ID и передает его в общую функцию-инициализатор (например, initializeComponent(element)), определенную в script.js.
JS-код компонента работает только в контексте переданного ему элемента (element.querySelector).
