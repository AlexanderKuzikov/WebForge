# WebForge — DECISIONS

<!-- Append-only. Формат фиксирован. -->

## 2026-05-03: webforge.json как SSOT

**Контекст:** Нужен единый источник истины для генерации сайта.

**Решение:** Один JSON-файл описывает всю структуру, контент, тему, медиа, schema.org.

**Альтернативы:** Markdown + frontmatter, YAML конфиги, CMS.

**Trade-off:** Большой файл, но единая точка управления для AI и человека.

## 2026-05-03: PHP для разработки, статика для деплоя

**Контекст:** Хостинг без Node.js, нужна автономность.

**Решение:** PHP include-based разработка, build.php генерирует чистый HTML/CSS/JS.

**Альтернативы:** Next.js SSG, Hugo, Eleventy.

**Trade-off:** Нет hot-reload, но zero-dependency на продакшене.

## 2026-09-22: CSS-нейминг — scoped-классы сразу, без авто-обёртки

**Контекст:** Открытые вопросы про нейминг компонентов и regex-парсинг CSS при сборке. Порт двух компонентов Storefront UI доказал: писать `c-{name}__element` сразу не мешает, сборка упрощается.

**Решение:** Компонентный CSS пишется сразу в скоупе `.c-{name}`. `build.php` ничего не оборачивает. `@keyframes`, `:root`, сбросы — только в глобальном CSS.

**Альтернативы:** Regex-обёртка при сборке, PHP CSS-парсер.

**Trade-off:** Дисциплина автора вместо автоматики; зато сборка не ломается на `@media` и псевдоэлементах.

## 2026-09-22: Первые компоненты — порт Blocks Storefront UI без зависимости

**Контекст:** Нужны первые переиспользуемые блоки раньше готовности генератора. Storefront UI даёт проверенный состав блоков, но тащить Vue/React/Tailwind нельзя.

**Решение:** Портировать идеи (состав ProductCard, Filters Sidepanel, логика usePagination, темизация через переменные), код писать с нуля. Результат: `components/product-card/`, `components/filters/`, `tools/pagination.php`, `assets/css/global.css`, `webforge.example.json`.

**Альтернативы:** Ждать генератора; брать Bootstrap-компоненты (списка нет в репо).

**Trade-off:** Ручная синхронизация с оригиналом, но zero-dependency сохранён. Лицензия ideas — MIT, код свой, атрибуция в шапках компонентов.
